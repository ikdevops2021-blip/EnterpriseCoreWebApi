## 2. Key Interactions to Verify

1. **Strict Sovereignty Fail-Closed Check:**
   - Send API request with `X-Organization-Id: 9999` (unregistered in `OrganizationDataResidency`).
   - Expected: API immediately rejects with `403 Forbidden` (`ERR_UNMAPPED_DATA_REGION`), preventing accidental un-sharded data writes.
2. **Regional DB Shard Resolution:**
   - Send request for EU Organization (101). Verify DB connection opens to the EU database cluster.
   - Send request for ME Organization (201). Verify DB connection opens to the ME database cluster without cross-tenant bleed.
3. **Transparent Field-Level Encryption & Decryption:**
   - Issue token with Customer Name "John Doe" and Phone "+15551234567".
   - Direct SQL inspection of `TokenTransaction` confirms `CustomerName` and `CustomerPhone` are encrypted binary ciphertext in `EncryptedCustomerName`/`EncryptedCustomerPhone`.
   - Calling staff token endpoint verifies "John Doe" and "+15551234567" are seamlessly decrypted for authorized tellers.
4. **Deterministic Blind Index Search:**
   - Query token by phone "+1 (555) 123-4567". Verify normalization to `+15551234567` produces matching HMAC-SHA256 blind index and retrieves the token in `< 2ms`.
5. **GDPR Article 17 Right-To-Be-Forgotten Execution:**
   - Execute erasure for phone "+15551234567".
   - Direct SQL inspection confirms:
     - `CustomerName` replaced with `'[ANONYMIZED-GDPR-ART17]'`
     - `CustomerPhone` replaced with `'[ANONYMIZED]'`
     - `EncryptedCustomerName`, `EncryptedCustomerPhone`, `PhoneBlindIndex` set to `NULL`
     - `IsAnonymized = 1`, `AnonymizedDate` set to current timestamp
     - `TAT`, `TokenNumber`, `QueuePosition`, `WaitTime`, `ServiceDuration` remain 100% intact
     - Record added to `GdprAuditLog`.
6. **Data Retention Scheduled Purge:**
   - Insert dummy token with `CreatedDate = GETDATE() - 100 days` and status `Completed (18007)`.
   - Run retention purge with `RetentionDays = 90`.
   - Verify token PII is scrubbed to `'[PURGED-RETENTION-POLICY]'` while keeping analytics counters intact.

## 3. Edge Cases

- **Edge Case E1: Tampered / Corrupted Ciphertext:**
  - Corrupt 1 byte in `EncryptedCustomerName`.
  - Service catches `CryptographicException` (AES-GCM auth tag mismatch), logs security alert, and returns safe fallback `[ENCRYPTED_DATA_CORRUPTED]` without crashing the API.
- **Edge Case E2: Un-normalized Phone Number Variations:**
  - Token issued with `+971 50 123 4567`. Erasure requested with `0501234567` or `+971-50-123-4567`.
  - Normalization engine converts both to standard E.164, ensuring blind index matches and erasure succeeds.
- **Edge Case E3: Concurrent Purge Lock Contention:**
  - High volume of active tokens (5,000+) during purge run.
  - Stored procedure uses `READPAST` and chunked `TOP (1000)` batches, ensuring zero deadlock or blocking on active teller workstations.
